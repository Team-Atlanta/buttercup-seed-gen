<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 1: Validate Java coverage in oss-crs deployment</name>
  <what-built>
Java coverage infrastructure (Phase 4) with comprehensive logging (Plan 05-01):
- helper.py language detection and dispatch
- JaCoCo agent execution
- XML report generation
- Logging throughout the pipeline
  </what-built>
  <how-to-verify>
**Option A: If Java test target available in CRSBench**

1. Start oss-crs deployment with a Java target:
```bash
cd ~/post/oss-crs/deployment
PROJECT=<java-project-name> make up
```

2. Watch coverage-bot logs for Java coverage execution:
```bash
# In another terminal
kubectl logs -n crs -l app=coverage-bot -f 2>&1 | grep -E "COVERAGE|Java"
```

3. Look for these log patterns confirming Java path:
- `Detected language 'java' for project`
- `Dispatching to JAVA coverage path`
- `=== Java Coverage Start ===`
- `JaCoCo exec file created`
- `XML report created`
- `=== Java Coverage Complete ===`

4. Verify XML report exists in the coverage task:
```bash
kubectl exec -it -n crs <coverage-bot-pod> -- ls -la /tmp/task*/fuzz-tooling/oss-fuzz/build/out/*/dumps/*.xml
```

**Option B: If no Java target available**

1. Verify C/C++ coverage still works (regression check):
```bash
cd ~/post/oss-crs/deployment
PROJECT=giflib make up
```

2. Watch coverage-bot logs:
```bash
kubectl logs -n crs -l app=coverage-bot -f 2>&1 | grep -E "COVERAGE|C\+\+"
```

3. Look for these patterns:
- `Detected language 'c' for project`
- `Dispatching to C/C++ LLVM coverage path`
- `=== C/C++ Coverage Start ===`
- `Profdata created`
- `=== C/C++ Coverage Complete ===`

4. Confirm logging is working and ready for Java when target available.

**In either case, note:**
- Which log messages appeared
- Any errors or warnings logged
- File sizes of .exec/.xml files if Java path taken
  </how-to-verify>
  <resume-signal>
Type "approved" if:

- C/C++ path regression test passed and Java validation deferred to when Java target available

If issues found, describe:

- What file was missing or empty
- Any actionable fixes needed
  </resume-signal>
</task>
